vrobot's forward speed (centre)

Odometry — Tracking Position with Encoders

Odometry uses encoders (sensors that count wheel rotations) to estimate where the robot is — like a robot's internal GPS, but calculated from movement instead of satellites.

🔢
Encoder counts pulses
Each click = tiny movement
📐
Calculate Δx, Δy, Δθ
Using kinematics formulas
📍
Update position
x, y, θ accumulate over time

Odometry Update Equations

$$\Delta x = v\cos\theta \cdot \Delta t \qquad \Delta y = v\sin\theta \cdot \Delta t \qquad \Delta\theta = \omega \cdot \Delta t$$ 
# Each time step, update the robot's position estimate:
new_x = old_x + Δx
new_y = old_y + Δy
new_θ = old_θ + Δθ
⚠️
Drift warning! Odometry errors accumulate over time — the longer the robot runs, the bigger the positional error. Real robots combine odometry with cameras or landmarks to stay accurate.

Encoder Distance Calculation Exam: 2021Q7

$$d = \frac{\text{encoder count} \times \pi \times D}{N}$$
ddistance travelled
Dwheel diameter
Nencoder resolution (pulses per full revolution)
counttotal pulses recorded
✏️ Worked Example
Wheel diameter $D = 6$ cm, encoder resolution $N = 360$ pulses/rev, encoder counted 720 pulses. How far did the robot travel?
$$d = \frac{720 \times \pi \times 6}{360} = 2\pi \times 6 \approx 37.7 \text{ cm}$$
✅ The robot travelled approximately 37.7 cm

Path Planning Algorithms

A* Algorithm

A* finds the shortest path from start to goal on a grid. It's smarter than simple search because it uses a heuristic (educated guess) to avoid exploring unnecessary paths.

$$f(n) = g(n) + h(n)$$
f(n)total estimated cost — always pick the lowest f next
g(n)actual cost from start to node n (known exactly)
h(n)estimated cost from n to goal (heuristic guess)

BFS vs DFS — Foundational Algorithms

🌊 BFS — Breadth-First Search
Explores outward layer by layer, like ripples on water. Checks all 1-step nodes, then all 2-step nodes, and so on.
✅ Guarantees shortest path
🕳️ DFS — Depth-First Search
Goes as deep as possible on one path first, then backtracks when it hits a dead end. Like exploring a maze without looking back.
💾 Memory efficient

Robot Motion Control Strategies

Go-to-Goal Algorithm

while not at_goal:
    # Step 1: figure out which way to face
    angle_error = target_angle - current_angle
    
    # Step 2: how far away is the target?
    distance = sqrt((tx - x)² + (ty - y)²)
    
    # Step 3: face the target first, then drive
    if angle_error > threshold:
        rotate to face target
    else:
        drive forward

Finite State Machines

A state machine breaks robot behaviour into distinct states, switching between them based on sensor input. It's simple, reliable, and easy to program — perfect for competitions!

Example: Obstacle-avoidance robot
➡️
State 1
Drive Straight
No obstacle
↩️
State 2
Turn Left
Obstacle ahead
↪️
State 3
Turn Right
Left also blocked
State 1 ── obstacle ahead ──▶ State 2
State 2 ── left side clear ──▶ State 1
State 2 ── left also blocked ──▶ State 3
State 3 ── right side clear ──▶ State 1

Competition-Ready State Machine

STATE_FOLLOW_LINE   → Normal line following
STATE_AVOID_LEFT    → Obstacle detected → go around left
STATE_AVOID_RIGHT   → Left also blocked → go around right
STATE_SEARCH_LINE   → After avoidance → re-acquire the line
STATE_STOP          → Task complete / emergency stop
