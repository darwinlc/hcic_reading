LiDAR — Laser Distance & Mapping Sensor

LiDAR stands for Light Detection And Ranging. It works on the same time-of-flight idea as ultrasonic — but uses laser light pulses instead of sound, and scans in all directions to build a full 2D map of the surroundings.

🤖
Fires laser pulses in all directions → measures time for each echo → builds a full distance map
$$d = \frac{c \times t}{2}$$
ddistance to obstacle (metres)
cspeed of light ≈ 3 × 10⁸ m/s
tround-trip travel time (seconds)
÷ 2light travels out AND back
Same formula as ultrasonic — only the wave speed changes (light is ~900,000× faster than sound).
🔊 Ultrasonic
✔ Cheap and simple
✔ Works in dark or fog
✘ One beam only — one distance at a time
✘ Short range (2 cm – ~4 m)
✘ Struggles with soft / angled surfaces
🔴 LiDAR
✔ Scans 360° — builds a full map
✔ Very accurate (< 1 cm error typical)
✔ Long range (up to 100+ m outdoors)
✘ More expensive
✘ Glass & mirrors can fool it
🚗
Real-world use: LiDAR is the "eyes" of self-driving cars and delivery robots. In competition robots it is used for SLAM — Simultaneous Localisation And Mapping — where the robot builds a map and figures out its own position at the same time.

Camera / Vision Sensor

A camera captures a full image every frame — giving the robot a rich picture of the whole scene at once, rather than a single measurement. The controller then uses software to extract useful information from that image.

🎨
Colour detection
Identify objects by colour (e.g. red block vs blue block in sorting tasks)
📐
Shape recognition
Find circles, squares, arrows — useful for target or goal detection
📷
Line / edge following
A wide-angle camera can follow a line far more precisely than two point sensors
🔲
QR / ArUco markers
Read codes placed in the arena to know position, task ID, or score zone
💡
Camera vs point sensor: A single camera can replace multiple line sensors, colour sensors, and IR sensors at the cost of needing a more powerful processor to handle the image data. Simple sensors are faster and cheaper for straightforward tasks.

Open Loop vs Closed Loop Control

❌ Open-Loop
📤 Command sent
↓
⚙️ Actuator acts
↓
🤷 Result ignored
No feedback — hopes for the best!

e.g. "Run motor for 1 second" — doesn't check if target was reached

✅ Closed-Loop
📤 Command sent
↓
⚙️ Actuator acts
↓
📡 Sensor checks result
↓
🔁 Error corrected → repeat
Continuously self-corrects!

e.g. Encoder measures position, motor keeps adjusting until target is reached

🏆
Competition tip: Closed-loop control is far more accurate and is used extensively in robot competitions. When in doubt, use feedback!
3.4 📊

PID Control

🚲
Think of riding a bicycle in a straight line.
You drift a little to the right — you steer left to correct. You don't spin the handlebars wildly; you steer just enough based on how far off you are. And if you were drifting for a long time, you correct a bit more. If you are already turning back fast, you ease off so you don't overshoot. PID is that exact same three-part thinking — built into the robot's brain.

PID is the most common way a robot continuously corrects itself. The robot checks: How far off am I? Have I been off for a long time? Am I getting better or worse? It uses those three answers to decide how hard to correct. Each letter handles one question:

P
Proportional
Looks at the current error right now. Bigger error → stronger push. Smaller error → gentle nudge.
🚲 "I've drifted 50 cm — steer a lot. I've drifted 2 cm — steer a tiny bit."
I
Integral
Keeps a running total of all past errors. If there's been a small drift that P couldn't fix, I slowly builds up extra correction.
🚲 "I've been slightly right of centre for the last 10 seconds — I must be fighting a side-wind, lean left a bit more."
D
Derivative
Watches how fast the error is changing. If the robot is rushing back to the target too quickly, D eases off so it doesn't overshoot.
🚲 "I'm snapping back really fast — ease off the handlebars or I'll swing to the other side!"

The PID Recipe (no calculus needed!)

RECIPE
Correction = P part + I part + D part
P part
= Kp × current error
"How far off am I right now?"
I part
= Ki × sum of all past errors
"Have I been off for a long time?"
D part
= Kd × change in error since last check
"Am I getting better or worse fast?"
Kp, Ki, Kd are numbers you choose (called gains) — bigger number = that part has more influence

Worked Example — Robot Tracking a Line

The robot should be at position 0 (centre of line). The sensor reads it is +8 cm to the right. Set Kp = 2, Ki = 0, Kd = 0 (P-only for now).

Error = target − actual = 0 − 8 = −8 cm

P correction = Kp × error = 2 × (−8) = −16

The robot steers left by a correction of 16 units — bigger drift → bigger steer. ✅

Tuning Steps for Competition

1️⃣
Start with P only — turn off I and D (set Ki = Kd = 0). Adjust Kp until the robot roughly reaches the target (it may wobble a bit — that's OK for now).
2️⃣
Add a little D — this acts like brakes. The robot stops swinging back and forth past the target (overshooting).
3️⃣
Add a tiny I only if needed — if the robot always stops a little short of the target (a "stubborn" leftover error), I slowly accumulates extra push to close the gap.
💡
Key idea: In most primary-level competitions, P-only (or P+D) is enough. You do not need to understand the maths behind I and D — just know what each letter does and why we might switch it on.

PWM Motor Control

💡
Imagine flicking a light switch very, very fast.
If you flick it ON for half a second, then OFF for half a second, the bulb appears to glow at half brightness. If you leave it ON for 9 tenths of a second and OFF for only 1 tenth, it appears nearly full brightness.

Motors work the same way. The controller switches the power on and off hundreds of times per second. The motor spins fast, so these tiny pulses feel like a steady, smooth power — just at a lower average level. That's all PWM is!

PWM = Pulse Width Modulation — a way to control motor speed by adjusting how much of each time-slice the power is ON. Exam: 2021Q5

How duty cycle controls speed:
25% duty
Slow — ON 1/4 of the time
50% duty
Half speed — ON half the time
100% duty
Full speed — ON all the time

Duty Cycle Formula

$$\text{Duty Cycle} = \frac{t_{\text{ON}}}{T} \times 100\%$$
tONtime the power is ON in one cycle (seconds)
Ttotal length of one cycle (seconds)
Example: ON for 3 ms, OFF for 7 ms → T = 10 ms → Duty Cycle = 3/10 × 100% = 30%

Motor Direction Control

A motor driver chip (called an H-bridge) uses two control pins (IN1, IN2) to choose direction, and PWM to choose speed. Think of IN1/IN2 like a two-way switch: one side makes it go forward, the other makes it reverse. 

# Motor direction — pseudocode

# Go FORWARD at 80% speed
IN1 = HIGH   # pin 1 ON  → sets direction to forward
IN2 = LOW    # pin 2 OFF
PWM = 80%   # 80% duty cycle → 80% speed

# Go REVERSE at 80% speed
IN1 = LOW    # pin 1 OFF → flips direction
IN2 = HIGH   # pin 2 ON
PWM = 80%

# STOP (both pins OFF → no current flows)
IN1 = LOW
IN2 = LOW

Practice Questions

Question 1
A robot's ultrasonic sensor sends a sound pulse. The echo returns after 0.006 seconds. How far away is the obstacle? (Speed of sound = 340 m/s)
A 2.04 m
B 1.02 m
C 0.51 m
D 4.08 m
Formula: $d = \dfrac{v \times t}{2}$

$d = \dfrac{340 \times 0.006}{2} = \dfrac{2.04}{2} = \mathbf{1.02 \text{ m}}$

We divide by 2 because the sound travels out to the obstacle and back — the round trip is twice the actual distance. ✅
Question 2
A PWM signal has a period of 20 ms. The power is ON for 5 ms. What is the duty cycle?
A 5%
B 20%
C 25%
D 75%
Formula: $\text{Duty Cycle} = \dfrac{t_{\text{ON}}}{T} \times 100\%$

$= \dfrac{5}{20} \times 100\% = \mathbf{25\%}$

25% duty cycle means the motor runs at roughly 25% of full speed. ✅
Question 3
In a line-following robot, the left sensor reads 0 (black) and the right sensor reads 1 (white). What should the robot do?
A Turn left
B Turn right
C Go straight
D Stop
Left = 0 means the left sensor is over the black line — the robot has drifted to the left.

To get back on track, the robot must turn right. ✅

Memory tip: the sensor that reads 0 (sees the line) is the side you've drifted toward — turn the other way.
Question 4
A robot's PID controller has Kp = 3, Ki = 0, Kd = 0. The robot is currently 4 cm to the left of the target line (error = +4 cm). What is the correction output?
A 4
B 3
C 12
D 7
With only the P part active:

Correction = Kp × error = 3 × 4 = 12

The correction output is 12 (steering right to get back on the line). The bigger the error, the stronger the correction — that's what "Proportional" means. ✅
Question 5
Which control system is more accurate for a robot that must stop at an exact position — open-loop or closed-loop? Why?
A Open-loop — it's simpler and faster
B Closed-loop — it uses sensor feedback to keep correcting until the target is reached
C Both are equally accurate
D Open-loop — it uses more sensors
Closed-loop is more accurate because it continuously checks its own position using a sensor.

Open-loop just sends a command (e.g. "run for 2 seconds") and hopes the robot ends up at the right place. If the floor is slippery or the battery is low, there's no correction.

Closed-loop detects any error and adjusts until the robot is actually at the target. ✅
📝 Chapter Summary — Key Points to Remember
Ultrasonic distance $$d = \frac{v \times t}{2}$$   (sound ≈ 340 m/s) — 1 beam, short range
LiDAR distance $$d = \frac{c \times t}{2}$$   (light ≈ 3×10⁸ m/s) — 360° scan, builds a map
Closed-loop control Sensor feedback → continuously correct error → more accurate
PID P = correct by current error  ·  I = correct built-up past error  ·  D = prevent overshoot
PWM duty cycle $$\text{Duty Cycle} = \frac{t_{\text{ON}}}{T} \times 100\%$$   (higher % = faster motor)
Line-following Sensor detects drift → differential correction (turn toward the line)
